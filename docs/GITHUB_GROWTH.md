# Distribution plan: meaningful adoption before rankings

There is no legitimate shortcut to becoming the #1 GitHub repository.
Artificial stars, mass spam and cloned testimonies are out of scope. Stars are
not equivalent to happy users. Aim to make the repository useful and easy to run.

## Preflight: source and trust

1. Import the complete tagged Git bundle into a **new public repository** named
   `aiwallet-release-lab` once the user's GitHub write connection is enabled.
   Do **not** overwrite unrelated repositories.
2. Enable CI matrix for Python 3.11, 3.12 and 3.13 with FFmpeg on all versions.
3. Verify installation from the tagged wheel on a fresh environment, no app keys.
4. Use a release attachment containing source ZIP, wheel, zipapp and SHA-256 file.
5. Verify hosted artifact bytes match local SHA-256 and publish test provenance.
6. Link BIMO *technical* case study with its caveat; do not claim artistic awards.

## Adoption loops

- Collect at least 10 independent creators' actual workflow failures before
  prioritizing advanced scoring; count installs and issues, not inflated stars.
- Provide Premiere/Resolve/CapCut export preflight profiles with public caveats.
- Accept reproducible minimal samples with private-video privacy preserved.
- Publish one issue/PR per real failure, labelled good-first-issue when scoped.
- Announce the free release in relevant developer/video-editor communities only
  where project announcements are allowed. Respond to feedback, no mass DM.
- Publish benchmarks on repeatable synthetic fixtures and OS/FFmpeg versions.
- Add examples for GitHub Actions, pre-commit, GitLab CI and self-hosted NAS.

## SaaS criteria

Only turn on real Creator Cloud/Studio Workspace billing when storage, tenant
isolation, retention, quota enforcement, cancellation, refunds, tax, real
subscription webhooks and payment-provider approval have passed staging tests.
The website currently collects **interest only**, without charges or cloud
uploads. Prices are hypotheses until enough qualifying prospects are interviewed.

## Success metrics

Weekly unique completed local audits; external test installations; median time
to first valid report; repeat weekly usage; issue resolution time; false alarms;
external PRs; conversion from voluntary waitlist to *verified* activated pilots.
A ranking claim requires an externally confirmed GitHub ranking with scope,
date and methodology, not a marketing sentence on our own page.
